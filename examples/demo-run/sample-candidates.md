# 候选清单（演示 · 生成前的一次复核）

> 由 `sample-evidence.json` 经「个人归因」后产出。**这是 Skill 在成稿前唯一一次交互**：先给编号候选让你复核，你可回「确认 / 删2 / 补充…… / 修改1……」。

本周候选工作（共 2 项）：

1. **[客户台账系统]** 确认三段式字段方案并推动联调 → 创建《字段规范 v2》→ 完成导入脚本自测（回填 2 个空值问题）→ 评审会发言并认领「异常 case 文档」→ 邮件向客户承诺周五交付初版
   - 来源：飞书消息 + WPS 文档 + 飞书任务 + 妙记 + 邮件（**跨源互证，强证据**）
2. **[周报自动化]** 回复排期，确认本周做数据采集、下周做归因
   - 来源：飞书消息（中证据）

**已排除 / 可能遗漏（接触 ≠ 参与，未计入产出）：**

| 痕迹 | 为什么不算你的产出 |
|---|---|
| 被 @ 问进度但未回复 | 被 @ ≠ 已处理 → 弱证据，仅标「可能遗漏」 |
| 《视觉规范》被共享给我、仅打开未编辑 | `created_by` 是同事 → 共享 / 打开 ≠ 你的产出 |
| 被邀请「季度 OKR 对齐会」但未参加 | 邀请 ≠ 参会 → 排除 |
| 「整理竞品调研」被分配但本周无进展 | 分配 ≠ 进展 → 排除 |
| 「全员通知群」团建讨论 | 群成员 ≠ 参与，群里他人消息不归你 → 排除 |

> 回复「确认」即按上面成稿；或「删2」「补充……」「修改1……」。
